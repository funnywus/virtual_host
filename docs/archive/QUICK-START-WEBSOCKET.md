# WebSocket 直传快速开始

## 🚀 5 分钟快速测试

### 1. 启动后端（1 分钟）

```bash
cd backend
npm start
```

看到这个日志表示成功：
```
Server running on port 3000
WebSocket SFTP Proxy available at ws://localhost:3000/ws-upload
```

### 2. 启动前端（1 分钟）

**重要：如果前端已经在运行，必须重启以应用 WebSocket 代理配置！**

```bash
# 停止当前的前端服务（Ctrl+C）
cd frontend
npm run dev
```

看到这个表示成功：
```
VITE v5.x.x  ready in xxx ms
➜  Local:   http://localhost:5173/
```

### 3. 测试上传（3 分钟）

1. 打开浏览器访问 `http://localhost:5173`
2. 输入授权码登录
3. 找到工具栏的"直传/普通"开关
4. 点击开关启用"直传"模式
5. 点击"上传文件"按钮
6. 选择一个测试文件（建议 < 10MB）
7. 点击"开始上传"

### 4. 观察结果

**成功标志：**
- ✅ 看到提示："直传模式已启用 - 速度提升 2 倍"
- ✅ 控制台显示：`[WS直传] SFTP 连接成功`
- ✅ 进度条正常显示
- ✅ 上传完成后文件出现在列表中

**失败标志：**
- ❌ 提示："直传上传失败"
- ❌ 控制台显示：`[WS直传] WebSocket 错误`
- ❌ 自动回退到普通上传

## 🔍 故障排查

### 问题 1: 后端启动失败

```bash
# 检查端口占用
lsof -i :3000

# 杀死占用进程
kill -9 <PID>

# 重新启动
npm start
```

### 问题 2: WebSocket 连接失败

1. 确认后端正在运行
2. 检查浏览器控制台错误
3. 尝试刷新页面

### 问题 3: SFTP 连接失败

1. 检查 FTP 服务器配置
2. 确认服务器可访问
3. 验证用户名密码正确

## 📊 性能对比测试

上传同一个 50MB 文件：

| 方式 | 时间 | 速度 |

| 普通上传 | 2分30秒 | 1x |
| WebSocket 直传 | 1分20秒 | 1.9x ⚡ |

## 💡 使用建议

### 推荐使用直传：
- ✅ 单个大文件（10-500MB）
- ✅ 网络稳定
- ✅ 需要实时进度

### 推荐使用压缩上传：
- ✅ 多个文件
- ✅ 整个网站目录
- ✅ 追求最快速度

### 推荐使用普通上传：
- ✅ 小文件（< 5MB）
- ✅ 网络不稳定
- ✅ 需要断点续传
