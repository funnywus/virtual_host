# 用户与权限

系统采用 JWT 无状态认证，区分管理员与普通用户两种角色。

## 认证流程

```
用户登录 → POST /api/auth/login
        → 后端验证 bcrypt 密码
        → 签发 JWT（有效期 24h）
        → 前端存储 Token（Pinia user store）
        → 后续请求 Header: Authorization: Bearer <token>
```

### 注册

```
POST /api/auth/register
Body: { username, email, password }
```

新用户默认角色为 `user`。生产环境建议关闭公开注册或仅由管理员创建用户。

## 角色说明

| 角色 | 标识 | 权限 |
|------|------|------|
| 管理员 | `admin` | 全部功能，含用户管理、系统设置 |
| 普通用户 | `user` | 域名、服务器、FTP 等日常功能 |

### 前端路由守卫

`admin/src/router/index.jsx` 中：

- 未登录访问受保护路由会重定向到 `/admin-jm/login`
- 非 admin 访问 users、settings 会重定向到 `/admin-jm/subdomains`

## 用户管理（仅 admin）

在 **用户管理** 页面（`/admin-jm/users`）：

- 查看用户列表
- 创建用户
- 修改角色
- 删除用户

API 前缀：`/api/users`（需 admin Token）

## 初始化管理员

首次部署必须创建管理员：

```bash
cd backend
node scripts/init-admin.js admin your_password admin@example.com
```

## 安全机制

### 密码存储

- 使用 **bcrypt** 哈希（cost factor 10）
- 数据库不存储明文密码

### JWT

- 密钥来自环境变量 `JWT_SECRET`（必填）
- Payload 包含：`id`、`username`、`role`
- 过期时间：24 小时

### 中间件

`backend/middleware/auth.js` 提供：

- `authenticateToken` — 验证 JWT
- 角色检查逻辑（部分路由限制 admin）

### 其他防护

- SQL 参数化查询，防 SQL 注入
- 文件路径校验，防目录 traversal
- CORS 已启用（开发环境前端直连后端）

## 环境变量

```env
JWT_SECRET=请使用至少 32 位随机字符串
```

> 切勿将 JWT_SECRET 提交到版本库。更换密钥会使所有已签发 Token 失效。

## 记住登录（可选）

前端 `frontend/src/utils/remember-credentials.js` 支持本地记住用户名（不含密码），具体行为视实现而定。

## 最佳实践

1. 首次登录后立即修改默认密码
2. 为每位运维创建独立账号，避免共享 admin
3. 定期轮换 JWT_SECRET（需全员重新登录）
4. 生产环境使用 HTTPS，防止 Token 被窃听
5. 限制 `/admin-jm` 路径的 IP 访问

## API 摘要

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | `/api/auth/login` | 登录 | 公开 |
| POST | `/api/auth/register` | 注册 | 公开 |
| GET | `/api/users` | 用户列表 | admin |
| POST | `/api/users` | 创建用户 | admin |
| PUT | `/api/users/:id` | 更新用户 | admin |
| DELETE | `/api/users/:id` | 删除用户 | admin |
