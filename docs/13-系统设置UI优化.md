# 系统设置 UI 评估与优化建议

> 范围：后台「系统设置」`frontend/src/views/Settings.vue`（约 1143 行）  
> 方法：对照现页实现 + 后台其余页面 + UI/UX 启发式（信息架构、危险操作、可达性、国内加载）  
> 日期：2026-08-13  
> 结论：**要优化，但不要再做视觉大改。**  
> 落地：方案 A 已于 2026-08-13 实施（`Settings.vue` + 全面检测改为只读巡检）。

---

## 1. 结论（先看这个）

系统设置页已经做过一轮独立视觉升级（Control Center：左侧导航、青绿强调色、玻璃卡片、指标条）。观感比域名/FTP 列表页更完整，**视觉不是当前瓶颈**。

真正要修的是：

1. **危险运维动作缺少确认**（会停 Nginx / 批量续期，点一下就跑）
2. **信息架构重复、按钮没有主次**（同一件事出现在多个 Tab）
3. **这一页像另一个产品**：字体、色板、布局与后台其余 `.card` 页不一致
4. **运行时拉 Google Fonts**：国内管理端可能慢或失败，刷新后字体会跳

不建议：再换一套字体/配色、上暗色大屏、把设置页做成营销站。运维控制台优先 **安全、可扫读、可回退**，不是「好看到忘不了」。

推荐路径：**保留现有青绿 Control Center 骨架，做一轮体验修补（方案 A）**。工作量大约 0.5–1 天，收益明显高于再视觉重做。

## 2. 现状：这页已经长什么样

页面分 5 个 Tab：证书续期 / 运维检测 / 维护工具 / 数据库备份 / 系统信息。

做得好的地方（建议保留）：

| 点 | 说明 |
|----|------|
| 分区导航 | 左侧 sticky 导航 + hint，比一长页堆卡片更适合运维 |
| 证书总览 | Hero 状态芯片 + 指标卡 + 到期着色表，扫一眼能判断风险 |
| 维护工具 | 一行一事 + 说明文字，比一排按钮清楚 |
| 备份删除 / 清理分片 | 已有确认框 |
| 空状态 | 检测前有 empty，证书表无数据有 empty |
| 按钮 loading | 多数异步操作有 `:loading`，能防连点 |
| 窄屏 | 960px 以下导航改横滑、卡片改单列 |

对照后台其余页（域名、FTP、服务器）：那些页仍是 `App.vue` 的 `.card` + Element Plus 表格 + 系统字体。设置页单独引入了 Sora / IBM Plex Sans、青绿 `#0f766e`、独立 hero。这是一次「单页设计系统」，还没铺到全后台。

## 3. 评估依据（skills 落到这页）

评估按运维后台来，不按落地页：

- 产品形态：管理员运维控制台，不是 SaaS 营销页
- 风格优先级：**数据密度 + 最小主义 + 高对比状态色**；玻璃质感可以有，但不能压过操作安全
- 字体方向：开发者工具更适合系统字体或 IBM Plex 本地化；不要运行时打 Google Fonts
- Vue 现状：`<script setup>` 已符合 Composition API；路由已懒加载。缺口是 Tab 状态没进 URL

落到本页的硬规则：

| 规则 | 本页现状 | 严重度 |
|------|----------|--------|
| 破坏性操作必须确认 | 「检测并停用过期」「立即处理过期子域名」「立即续期」无确认 | 高 |
| URL 反映当前视图 | Tab 只存在内存，刷新/分享会丢 | 高 |
| 当前区块有明确选中态 | 左侧 nav active 有 | 中（已过） |
| 异步要有反馈 | 按钮 loading + toast 基本有；系统信息失败只打 console | 中 |
| 焦点可见 | `.nav-item { appearance: none }` 无 `:focus-visible` | 高 |
| 尊重减少动效 | `rise` 入场动画无 `prefers-reduced-motion` | 中 |
| 不要只靠颜色表达状态 | 到期天数主要靠红/橙/绿字 | 中 |
| 主按钮要少 | 运维检测一排 7 个同等按钮 | 高 |
| 运行时字体 CDN | `@import` Google Fonts | 高（国内） |

## 4. 问题清单

### P0 — 会误操作、会伤站

| ID | 问题 | 位置 | 建议 |
|----|------|------|------|
| S-01 | 「检测并停用过期」直接 `POST /system/diagnose/expire`，会禁 Nginx | 运维检测 `runExpire` | 确认框写清：禁站点、保留 DNS、列出将处理数量 |
| S-02 | 维护工具「立即处理过期子域名」同样无确认，且与 S-01 是同一 API | 维护工具 | 与 S-01 共用确认；工具区可只留入口、检测区只展示结果 |
| S-03 | 「立即检查并续期 / 立即执行证书自动续期」无确认 | 证书续期 + 维护工具 | 开关关闭时应提示「仅检查不续期」；开启时提示将续哪些窗口内证书 |
| S-04 | 运维检测按钮无主次：「一键全面检测」应是主操作，「检测并停用过期」应是危险操作，「刷新统计」应是次要 | `action-grid` | 主 / 次 / 危险三档；危险用 `type="danger"` 或明确文案 |

### P1 — 结构重复、用着费劲

| ID | 问题 | 说明 | 建议 |
|----|------|------|------|
| S-05 | 同一动作出现两次 | 过期停用、证书立即执行同时在「检测」和「工具」 | 工具 Tab 只放清理分片、备份类维护；巡检类只放检测 Tab |
| S-06 | 证书表在两个 Tab 重复 | 检测结果里的 SSL 表 ≈ 证书续期 Tab | 检测 Tab 只出摘要 + 「去证书续期」跳转 |
| S-07 | Tab 不进 URL | `/admin-jm/settings` 刷新永远回证书续期 | `?tab=diagnose`；浏览器后退应切 Tab |
| S-08 | 进页就打 4 个接口 | `onMounted` 同时拉备份、系统信息、统计、证书 | 按 Tab 懒加载 |
| S-09 | `running.ssl` 被两处共用 | 「同步服务器状态」和「证书续期时间检测」抢同一个 loading | 拆成独立 flag |
| S-10 | 连通性 Tag 语义反了 | `success/failed` 写成 `12/3`，看起来像成功/总数 | 改成「正常 12 · 失败 3」，失败为 0 用 success tag |
| S-11 | 指标卡不能点 | 「已过期 / 即将续期」不能筛表 | 点击指标过滤表格，或滚到对应行 |
| S-12 | 证书表无搜索 | 主域名多时 480px 滚动不好找 | 域名搜索框；可按 urgency 筛 |
| S-13 | 审计日志后端有、前端无 | `GET /api/system/audit-logs` 无页面 | 本轮可不做；若做，作为第 6 个 Tab，不要塞进系统信息 |

### P2 — 一致性和可达性

| ID | 问题 | 建议 |
|----|------|------|
| S-14 | Google Fonts `@import` | 改用系统字体栈（与 `MainLayout` 的 SF Pro / PingFang 对齐），或自托管 woff2 |
| S-15 | 英文 eyebrow「Control Center」 | 全中文后台里突兀，改为「运维中心」或删掉 |
| S-16 | 版本号三处不一致 | 侧栏 footer `v1.0.0`，设置页默认 `2.0.0`，文档写 v2.0.0 | 只展示接口返回的版本 |
| S-17 | 备份路径写 `backend/backups` | 对操作员无意义 | 改成「保存在服务器备份目录」，路径给管理员看详情 |
| S-18 | 导航不是 tab 语义 | 应用 `role="tablist"` / `aria-selected`；当前项 `aria-current` |
| S-19 | 自定义 nav 无焦点环 | `:focus-visible { outline / box-shadow }` |
| S-20 | 入场动画无减少动效 | `@media (prefers-reduced-motion: reduce)` 关掉 `rise` |
| S-21 | 到期状态只靠颜色 | 保留颜色，补「已过期 / 即将到期」文字（表里其实有，保持 tag + 文字即可） |
| S-22 | 系统信息加载失败静默 | `loadSystemInfo` 只 `console.error` | 页内错误条 |
| S-23 | 开关变更立即保存 | 体验可以留，但失败时开关应回滚（当前 catch 后本地值可能已变） |
| S-24 | Element Plus 默认蓝按钮 vs 页内青绿 | 主按钮覆盖为 `--accent`，避免一页两套主色 |

## 5. 三种做法（选一个）

### 方案 A — 体验修补（推荐）

保留现有布局和青绿卡片，只改交互和文案。

做：S-01～S-04、S-05～S-10、S-14、S-15、S-18～S-20。  
不做：全后台换肤、暗色、新字体、审计日志。

理由：设置页视觉已经可用；误操作和按钮墙才是管理员会骂的点。YAGNI。

### 方案 B — 收回与其它页一致

拆掉 hero / 独立字体 / 左侧 nav，改回 `.card` + `el-tabs`，和域名/FTP 一样。

适合：你觉得设置页「花了」，想全后台先统一再慢慢升级。  
代价：丢掉已经做好的分区扫读；工作量和方案 A 差不多，但体验不一定更好。

### 方案 C — 抽出设计系统再铺全后台

把设置页 token（色、圆角、卡片、导航）抽到全局，域名/子域名跟着改。

适合：明确要做下一阶段 UI 统一。  
现在不要做：子域名页仍是性能和同步问题优先（见 `docs/12-子域名管理性能优化.md`）。

**默认选 A。** 若你更在意「设置页不要特殊」，选 B。

## 6. 方案 A 的目标界面（不改代码前的约定）

### 信息架构

```
系统设置
├── 证书续期     开关 / 提前天数 / 巡检时刻 / 证书表 / 单域名续期
├── 运维检测     指标 / 一键巡检 / 分项检测 / 结果（SSL 只出摘要）
├── 维护工具     清理分片；过期停用改为「到运维检测执行」或带强确认的快捷入口
├── 数据库备份   备份 / 下载 / 删除
└── 系统信息     运行时；失败可见
```

URL：`/admin-jm/settings?tab=ssl|diagnose|tools|backup|info`

### 运维检测按钮层级

1. **主**：一键全面检测  
2. **次**：服务器连通 / DNS / 站点健康 / 刷新统计  
3. **危险**：检测并停用过期（需确认）  
4. 证书相关检测：改成链到证书 Tab，或只更新摘要、不复制整表

### 确认文案（过期停用）

标题：停用过期站点  
正文：将禁用这些站点的 Nginx，DNS 记录保留，站点可再启用。  
列出数量（来自统计 `expired_active`）。确认按钮用危险样式。

### 视觉（只收口，不重做）

- 去掉 Google Fonts，继承后台系统字体
- 主色继续用页内 `--accent: #0f766e`，把 `el-button--primary` 对齐
- 导航补 focus-visible；动效尊重减少动画
- 英文 Control Center 改中文或删除

### 不做

- 新字体配对、暗色 OLED、热力图、骨架屏大改
- 把设置页审美铺到子域名列表（那页先看 docs/12）
- 审计日志（单独需求再开）

## 7. 建议实施顺序

若按方案 A 改，建议分三批，每批可独立验收：

**批次 1（安全，先做）**  
S-01～S-04 确认框与按钮层级。不过视觉也能上。

**批次 2（结构）**  
S-05～S-10：去重、Tab 入 URL、按需加载、Tag 文案。

**批次 3（收口）**  
S-14 去 Google Fonts、S-15 中文、S-18～S-20 可达性、S-22 错误态、S-24 主色对齐。

验收：

- 未确认不能停用过期站、不能跑自动续期
- 刷新后仍停在当前 Tab
- 断网或 Fonts 被墙时页面不闪、不空白
- 键盘 Tab 能看见导航焦点
- 运维检测页不再出现第二张完整证书表

## 8. 和「要不要优化」的直接回答

| 问题 | 回答 |
|------|------|
| 要不要优化？ | **要。** 优先交互和结构，不是再美化。 |
| 现在丑吗？ | 不丑。比域名/FTP 列表更完整，但像另一个产品。 |
| 要不要推倒重做？ | **不要。** |
| 最小值得做的是什么？ | 危险操作确认 + 按钮主次 + 去掉 Google Fonts。 |
| 全后台统一皮肤现在做吗？ | 不建议。子域名性能（docs/12）更优先。 |

改之前若只能选一件：**给「停用过期站点」加确认框。**
